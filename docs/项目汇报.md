## 一、项目概述

**小账本**是一个用于记录日常开销的单页 Web 应用（SPA）：用户可以「记一笔」开销，按月份和分类筛选查看明细，查看总额与分类占比，并把当前筛选出的明细导出为 CSV 文件。

项目的自身定位见 `package.json` 描述：*「小账本：用于演示 dsh-superagent 的前端示例项目」*——它是一个结构完整、逻辑清晰、带测试和 CI 的小型前端样板工程，而非需要长期运营的业务系统。

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 小账本（`ledger-demo`） |
| 版本 | 0.1.0 |
| 技术栈 | Vite 7 + React 19 + TypeScript 5.9，单元测试 Vitest 3 |
| 数据存储 | 浏览器 `localStorage`，无后端、无账号体系；CSV 导出为本地文件 |
| 运行形态 | 纯静态前端，构建产物为静态文件，自动发布到 GitHub Pages |
| 在线地址 | `https://<用户名>.github.io/dsh-demo-app/`（由 GitHub Actions 部署） |
| 界面语言 | 简体中文 |

## 二、功能梳理

### 2.1 功能清单

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 记账 | 新增一笔开销 | 输入金额（元）、分类、日期、备注；提交时校验，不通过显示错误提示 |
| 记账 | 删除一笔开销 | 明细表中每行提供「删除」按钮 |
| 记账 | 分类 | 固定六类：餐饮、交通、购物、住房、娱乐、其他 |
| 筛选 | 按月份筛选 | 下拉选择「全部月份」或已有记录中出现过的月份（从新到旧） |
| 筛选 | 按分类筛选 | 下拉选择「全部分类」或某个分类 |
| 统计 | 合计 | 显示当前筛选结果的总额与笔数 |
| 统计 | 分类占比 | 按分类金额从高到低列出金额与百分比，并用条形图展示占比 |
| 明细 | 明细列表 | 按日期从新到旧排序，展示日期、分类、备注、金额 |
| 导出 | 导出 CSV | 明细标题栏的「导出 CSV」按钮（绿色），把**当前筛选结果**导出为 CSV 文件；无记录时按钮禁用 |
| 数据 | 本地持久化 | 每次变更自动写入 `localStorage`，刷新后仍在 |
| 数据 | 示例数据 | 首次打开（无本地数据）时展示本月和上个月共 7 条示例记录 |
| 数据 | 重置示例数据 | 顶部按钮（绿色）一键恢复为示例数据并清空筛选条件 |
| 发布 | 在线预览 | 合并到 `main` 后自动构建并发布到 GitHub Pages |

### 2.2 关键业务规则

这些规则既是功能约束，也是后续开发的契约，集中体现在 `src/lib/ledger.ts`、`src/lib/money.ts` 与 `src/lib/csv.ts`：

1. **金额以「分」为单位、用整数存储**，只在输入解析（`parseAmount`）、展示（`formatMoney`）和导出（`formatCentsForCsv`）时与「元」互转，避免浮点误差。
2. **金额输入格式**：非负数字（整数部分必需），最多两位小数；解析失败或小于等于 0 均拒绝。
3. **金额换算不经过浮点乘法**：`parseAmount` 把「元」「角分」两段拼成整数分（如 `0.29` → 29），因为 `0.29 * 100` 会得到 `28.999999999999996`；超出 JavaScript 安全整数范围（`Number.MAX_SAFE_INTEGER`）的金额拒绝录入。
4. **金额显示按字符串分段**：`formatMoney` 不经过除法取整，保证分位补零（`5` → `¥0.05`）和大数不出现指数形式；传入非整数分、`NaN`、`Infinity` 或超大数时统一显示 `¥0.00`，不会产生乱码。
5. **日期以本地时区的 `YYYY-MM-DD` 字符串保存**，因此可以直接按字符串比较排序（`src/lib/date.ts`）。注意：不使用 `toISOString()`，避免 UTC 时区导致「日期差一天」。
6. **备注**去掉首尾空格后最多 30 字。
7. **筛选与统计联动**：统计基于「筛选后的可见记录」计算，而不是全量数据。
8. **排序**：明细按日期从新到旧；同一天的记录保持原有顺序（排序比较函数只比较日期，依赖 `Array.prototype.sort` 的稳定性）。
9. **数据容错**：读取 `localStorage` 时若 JSON 损坏返回空列表，并逐条丢弃字段不合法的记录。
10. **导出内容与页面一致**：CSV 导出的是当前筛选后、已按日期降序排列的明细，不重新排序；文件名按筛选月份命名。

### 2.3 导出 CSV 的规则

导出逻辑在 `src/lib/csv.ts`（纯函数）与 `src/components/ExportButton.tsx`（下载动作）中，规则如下：

| 项 | 规则 |
| --- | --- |
| 列 | 固定四列：`日期`、`分类`、`备注`、`金额（元）` |
| 金额 | 转成两位小数的「元」字符串（如 `1234.56`），不带 `¥` 和千分位，方便表格软件直接识别为数字 |
| 行尾 | CRLF（与 Excel 习惯一致）；每条记录一行 |
| 转义 | 单元格含逗号、双引号或换行时用双引号包裹，内部双引号写两遍 |
| 公式注入防护 | 备注以 `=`、`+`、`-`、`@`、制表符或回车开头时，前面加一个单引号，避免被表格软件当作公式执行 |
| 编码 | 文件带 UTF-8 BOM（`\uFEFF`），Excel 打开中文不乱码 |
| 文件名 | 选了月份时 `小账本-YYYY-MM.csv`；全部月份时 `小账本-全部月份.csv` |
| 空列表 | 按钮禁用，不生成文件 |
| 资源释放 | 下载触发后立即 `URL.revokeObjectURL` 释放临时地址 |

## 三、架构设计

### 3.1 总体架构

这是一个**纯前端、无后端**的分层架构：浏览器渲染 UI，业务逻辑全部在浏览器里以纯函数实现，数据落在 `localStorage`，导出由浏览器生成文件下载，构建与发布由 Vite 和 GitHub Actions 完成。

```
                ┌──────────────────────────────────┐
                │             浏览器                │
                │                                  │
  用户操作 ───▶ │  React 组件层 (components/)       │
                │   ExpenseForm / Filters /        │
                │   Summary / ExpenseList /        │
                │   ExportButton                   │
                │            │ props 回调           │
                │            ▼                     │
                │  App.tsx：状态与组装               │
                │   useState / useMemo / useEffect │
                │            │                     │
                │            ▼                     │
                │  纯逻辑层 (lib/)                  │
                │   money / date / ledger /        │
                │   csv / storage / sample         │
                └──────┬──────────────┬───────┬────┘
                       │              │       │
               localStorage      CSV 文件下载  静态资源 (dist)
                                                   │
                                        GitHub Actions → GitHub Pages
```

### 3.2 分层职责

设计原则（见 `AGENTS.md`）：**业务逻辑放在 `src/lib/` 写成纯函数并配测试，组件只负责展示和交互。**

| 层次 | 位置 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 入口 | `index.html`、`src/main.tsx` | 挂载 React 根节点，开启 `StrictMode` | — |
| 页面组装 | `src/App.tsx` | 持有账本状态与筛选状态，计算派生数据，串联各组件（含导出按钮） | `lib/*` |
| 展示组件 | `src/components/*.tsx` | 表单、筛选、统计、明细表、导出按钮；只接收 props、发出回调 | `lib/*` 中的纯函数与类型 |
| 领域逻辑 | `src/lib/money.ts`、`date.ts` | 金额、日期的基础工具 | 无 |
| 领域逻辑 | `src/lib/ledger.ts` | 类型定义、校验、筛选、排序、月份列表、统计、ID 生成 | `money`、`date` |
| 导出逻辑 | `src/lib/csv.ts` | 记录 → CSV 文本、CSV 金额格式、文件名、公式注入防护 | `ledger`（类型） |
| 持久化 | `src/lib/storage.ts` | `localStorage` 读写与数据校验 | `ledger` |
| 示例数据 | `src/lib/sample.ts` | 按当前日期生成示例记录 | `date`、`ledger`（类型） |
| 样式 | `src/App.css` | 全局样式与布局，CSS 变量定义主题/强调/成功/危险色 | — |
| 构建 / 部署 | `vite.config.ts`、`.github/workflows/*.yml` | 相对基路径构建；CI 校验与 GitHub Pages 发布 | — |

### 3.3 数据流与状态管理

没有引入 Redux、Zustand 等状态管理库，**用 React 内置能力实现单向数据流**：

1. **状态**：`App` 维护两个状态——`expenses`（全部记录）和 `filter`（当前筛选条件）。
2. **派生数据**：用 `useMemo` 从状态计算 `visible`（筛选 + 排序）、`summary`（统计）、`months`（可选月份），避免重复计算，也不额外保存冗余状态。`visible` 同时供明细表、统计和导出使用，保证三处看到的内容一致。
3. **向下传数据、向上传事件**：父组件通过 props 传入数据和回调（`onAdd`、`onDelete`、`onChange`），子组件不直接改动父状态；`ExportButton` 接收 `items`（可见记录）和 `month`（筛选月份），只负责下载动作。
4. **表单局部状态**：`ExpenseForm` 自己维护未提交的草稿和错误提示，调用纯函数 `validateDraft` 校验通过后，才通过 `onAdd` 交给父组件。
5. **持久化**：`useEffect` 监听 `expenses`，每次变化即写回 `localStorage`（`storage.ts` 中以 key `ledger.expenses.v1` 保存）。

数据写入路径：

```
表单输入 → 点「添加」→ validateDraft() ─失败→ 显示错误
                                   └成功→ onAdd(expense) → App.addExpense()
                                        → 生成 id → setExpenses(...)
                                        → 重新计算 visible / summary
                                        → useEffect → saveExpenses(localStorage, ...)
```

导出路径：

```
点「导出 CSV」→ ExportButton.exportCsv()
   → items 为空则直接返回（按钮本身也禁用）
   → expensesToCsv(items)  → 表头 + 每行记录（转义、防公式注入、行尾 CRLF）
   → 加 UTF-8 BOM 生成 Blob → createObjectURL → <a download=csvFileName(month)> 触发下载
   → revokeObjectURL 释放临时地址
```

### 3.4 数据模型

```ts
interface Expense {
  id: string        // 唯一 ID：时间戳(36 进制) + 随机串，由 newId() 生成
  amount: number    // 金额，单位：分（整数，安全整数范围内）
  category: Category // '餐饮' | '交通' | '购物' | '住房' | '娱乐' | '其他'
  note: string      // 备注，去空格后 ≤ 30 字，可为空
  date: string      // 本地日期 'YYYY-MM-DD'
}

interface ExpenseFilter {
  month: string            // 'YYYY-MM'，'' 表示全部月份
  category: Category | 'all'
}

interface Summary {
  total: number            // 总额（分）
  count: number            // 笔数
  byCategory: { category; amount; percent }[]  // 按金额降序，percent 取整
}
```

存储格式为上述 `Expense[]` 的 JSON 数组，带版本号的 key（`v1`）为未来数据迁移预留了位置。CSV 是导出格式而非存储格式：`日期, 分类, 备注, 金额（元）`，金额以两位小数的元表示。

### 3.5 设计取舍

| 取舍 | 做法 | 原因 |
| --- | --- | --- |
| 无后端 | 数据只存 `localStorage`，导出为本机文件 | 示例项目定位；零部署成本，打开即用 |
| 金额用整数分 | `parseAmount` / `formatMoney` / `formatCentsForCsv` 边界转换 | 避免 `0.1 + 0.2` 这类浮点误差 |
| 金额按字符串分段换算 | 不经过浮点乘除 | 规避 `0.29 * 100` 与 `1e21` 的指数显示等边界问题 |
| 日期用字符串 | 本地 `YYYY-MM-DD`，字符串排序 | 简单、可比较，且不受时区影响 |
| 逻辑与视图分离 | `lib/` 纯函数 + `components/` 展示 | 业务规则可单测；CSV 文本生成不碰 DOM，便于测试 |
| 依赖注入 `storage` | 存储函数接收 `storage` 参数 | 测试时传入内存假对象，不需要浏览器环境 |
| 无状态管理库 | `useState` + `useMemo` + props | 状态量小，避免过度设计 |
| 运行时不引第三方库 | 仅 `react`、`react-dom`；CSV 自行实现 | `AGENTS.md` 明确要求「不要新增运行时依赖」，Excel 兼容规则可控 |
| 导出当前筛选结果 | 导出拿 `visible`，文件名带筛选月份 | 所见即所得，可先把 CSV 当作按月备份的手段 |
| 相对基路径 `base: './'` | 构建产物资源路径相对 | 同时兼容本地预览（`/`）与 GitHub Pages 子路径（`/<repo>/`），无需硬编码仓库名 |
| 绿色按钮 | 导出、重置示例数据使用 `--success` | 区分「主要但不常见」的操作与普通操作 |

### 4.4 CI 与发布

- **CI（`.github/workflows/ci.yml`）**：在 `push` 到 `main` 与所有 `pull_request` 时，于 `ubuntu-latest` + Node 22 上依次执行 `npm ci`、类型检查、测试、`vite build`；权限仅 `contents: read`。
- **发布（`.github/workflows/deploy-pages.yml`）**：`push` 到 `main` 或手动触发（`workflow_dispatch`）时，先做类型检查、测试和构建，再通过 `actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages` 把 `dist/` 发布到 GitHub Pages；`concurrency` 组 `pages` 保证同一时间只发布一次、不打断进行中的发布；作业分为 `build` 与 `deploy` 两段，`deploy` 使用 `github-pages` environment。
- **首次启用**：需在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**；仓库为 Private 时还需要账号套餐支持 Pages。

### 4.5 协作约定

`AGENTS.md` 规定了「给编程 agent 的约定」：依赖用 `npm ci` 安装；提交前 `npm run check` 全绿；业务逻辑写在 `src/lib/` 并补测试；修 bug 先写复现测试；金额用分、日期用本地字符串；界面文案用简体中文；不加运行时依赖除非 Issue 明确要求；PR 描述写清楚改了什么、为什么、怎么验证。

构建产物 `dist/` 为纯静态文件。当前部署方式是 **GitHub Actions 自动发布到 GitHub Pages**（合并到 `main` 后生效，地址 `https://<用户名>.github.io/dsh-demo-app/`）；也可以手动把 `dist/` 托管到 Vercel、Netlify 或任意静态服务器。

由于数据存在浏览器 `localStorage`，**换浏览器、清缓存或换设备数据即丢失**，且不跨设备同步；`localStorage` 按站点域名隔离，本地开发与线上站点的数据互不相通。CSV 导出可作为按月的本地备份，但暂不支持导入回应用。

## 六、现状评估

### 6.1 优点

- **结构清晰、职责分明**：UI 与业务逻辑严格分层，模块小（最大 107 行），容易上手和扩展；导出这类新功能只新增 `lib/csv.ts` + `components/ExportButton.tsx` 两个文件，未改动既有逻辑。
- **契约明确**：金额、日期、分类、CSV 格式等核心规则集中定义并有测试保护，新增功能时不易破坏已有规则。
- **可测试性好**：纯函数 + 依赖注入（`storage`），测试不需要浏览器，跑得快；CSV 生成与下载动作分离，文本生成全部可单测。
- **边界处理扎实**：金额换算规避浮点误差与超大数，CSV 处理 Excel 兼容（BOM、CRLF）、转义与公式注入。
- **工程化完整**：类型严格、单元测试、构建校验、CI 齐全，`npm run check` 一条命令即可验证；合并即自动发布，可在线浏览。
- **轻量**：运行时仅两个依赖，未为 CSV 引入额外库。

### 6.2 已知限制

| 类别 | 限制 | 影响 |
| --- | --- | --- |
| 数据 | 只存本地浏览器，无备份、无跨设备同步 | 清缓存或换设备即丢失；无法多人共享 |
| 数据 | 有 CSV 导出但没有导入，无编辑功能 | 无法把导出的数据导回或在应用内修改，录错需删掉重录 |
| 功能 | 仅支出，无收入、预算、分类自定义 | 只适合简单记账 |
| 功能 | 不能按日期区间、关键词筛选/搜索 | 记录多时查找不便；导出只能按月或全部 |
| 功能 | 删除无二次确认 | 误删不可恢复 |
| 展示 | 明细只显示日期，不显示月份分组 | 跨月查看时略不直观 |
| 工程 | 组件层无测试 | 组件交互、下载动作回归只能靠人工验证 |
| 工程 | 无 ESLint/Prettier | 代码风格靠约定，无自动检查 |
| 部署 | GitHub Pages 首次需手动开启；Private 仓库需套餐支持 | 首次接入有一次性配置 |

> 以上为客观梳理，不代表必须修改；部分限制符合「示例项目」的定位。

### 6.3 后续可演进方向（建议）

1. **数据安全**：在 CSV 导出基础上增加 JSON 导入/导出（完整保留 id 与金额字段）、删除二次确认，降低数据丢失风险。
2. **编辑能力**：复用 `ExpenseForm` 实现记录的编辑。
3. **导出增强**：支持按日期区间导出、导出统计汇总行。
4. **存储版本迁移**：`STORAGE_KEY` 已带 `v1`，可在模型变更时补迁移函数。
5. **多端/多人（如确有需要）**：引入后端与账号体系，架构上需在 `lib/storage.ts` 处抽象为「仓储接口」，组件层不受影响。
6. **工程补强**：引入 ESLint/Prettier 与组件级测试（Testing Library），纳入 CI。
