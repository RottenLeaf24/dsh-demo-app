## 一、项目概述

**小账本**是一个用于记录日常开销的单页 Web 应用（SPA）：用户可以「记一笔」开销，按月份和分类筛选查看明细，并看到总额与分类占比。

项目的自身定位见 `package.json` 描述：*「小账本：用于演示 dsh-superagent 的前端示例项目」*——它是一个结构完整、逻辑清晰、带测试和 CI 的小型前端样板工程，而非需要长期运营的业务系统。

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 小账本（`ledger-demo`） |
| 版本 | 0.1.0 |
| 技术栈 | Vite 7 + React 19 + TypeScript 5.9，单元测试 Vitest 3 |
| 数据存储 | 浏览器 `localStorage`，无后端、无账号体系 |
| 运行形态 | 纯静态前端，构建产物为静态文件，可部署到任意静态托管 |
| 界面语言 | 简体中文 |

## 二、功能梳理

### 2.1 功能清单

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 记账 | 新增一笔开销 | 输入金额（元）、分类、日期、备注；提交时校验，不通过显示错误提示 |
| 记账 | 删除一笔开销 | 明细表中每行提供「删除」按钮 |
| 记账 | 分类 | 固定六类：餐饮、交通、购物、住房、娱乐、其他 |
| 筛选 | 按月份筛选 | 下拉选择「全部月份」或已有记录中出现过的月份（从新到旧） |
| 筛选 | 按分类筛选 | 下拉选择「全部分类」或某个分类 |
| 统计 | 合计 | 显示当前筛选结果的总额与笔数 |
| 统计 | 分类占比 | 按分类金额从高到低列出金额与百分比，并用条形图展示占比 |
| 明细 | 明细列表 | 按日期从新到旧排序，展示日期、分类、备注、金额 |
| 数据 | 本地持久化 | 每次变更自动写入 `localStorage`，刷新后仍在 |
| 数据 | 示例数据 | 首次打开（无本地数据）时展示本月和上个月共 7 条示例记录 |
| 数据 | 重置示例数据 | 顶部按钮一键恢复为示例数据并清空筛选条件 |

### 2.2 关键业务规则

这些规则既是功能约束，也是后续开发的契约，集中体现在 `src/lib/ledger.ts` 与 `src/lib/money.ts`：

1. **金额以「分」为单位、用整数存储**，只在输入解析（`parseAmount`）和展示（`formatMoney`）时与「元」互转，避免浮点误差。
2. **金额输入格式**：非负数字，最多两位小数；解析失败或小于等于 0 均拒绝。
3. **日期以本地时区的 `YYYY-MM-DD` 字符串保存**，因此可以直接按字符串比较排序（`src/lib/date.ts`）。注意：不使用 `toISOString()`，避免 UTC 时区导致「日期差一天」。
4. **备注**去掉首尾空格后最多 30 字。
5. **筛选与统计联动**：统计基于「筛选后的可见记录」计算，而不是全量数据。
6. **排序**：明细按日期从新到旧；同一天的记录保持原有顺序（排序比较函数只比较日期，依赖 `Array.prototype.sort` 的稳定性）。
7. **数据容错**：读取 `localStorage` 时若 JSON 损坏返回空列表，并逐条丢弃字段不合法的记录。

### 2.3 页面结构

单页面、三栏（窄屏下堆叠）布局：

```
┌──────────────────────────────────────────────┐
│ 小账本                          [重置示例数据] │
├──────────────┬───────────────────────────────┤
│ 记一笔        │ 统计                           │
│  金额/分类/   │  [月份筛选] [分类筛选]          │

└──────────────────────────────────────────────┘
```

## 三、架构设计

### 3.1 总体架构

这是一个**纯前端、无后端**的分层架构：浏览器渲染 UI，业务逻辑全部在浏览器里以纯函数实现，数据落在 `localStorage`，构建由 Vite 完成。

```
                ┌──────────────────────────────┐
                │          浏览器               │
                │                              │
  用户操作 ───▶ │  React 组件层 (components/)   │
                │   ExpenseForm / Filters /    │
                │   Summary / ExpenseList      │
                │            │ props 回调       │
                │            ▼                 │
                │  App.tsx：状态与组装           │
                │   useState / useMemo / useEffect
                │            │                 │
                │            ▼                 │
                │  纯逻辑层 (lib/)              │
                │   money / date / ledger /    │
                │   storage / sample           │
                └──────┬──────────────┬────────┘
                       │              │
               localStorage      静态资源 (dist)
```

### 3.2 分层职责

设计原则（见 `AGENTS.md`）：**业务逻辑放在 `src/lib/` 写成纯函数并配测试，组件只负责展示和交互。**

| 层次 | 位置 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 入口 | `index.html`、`src/main.tsx` | 挂载 React 根节点，开启 `StrictMode` | — |
| 页面组装 | `src/App.tsx` | 持有账本状态与筛选状态，计算派生数据，串联各组件 | `lib/*` |
| 展示组件 | `src/components/*.tsx` | 表单、筛选、统计、明细表；只接收 props、发出回调 | `lib/*` 中的纯函数与类型 |
| 领域逻辑 | `src/lib/money.ts`、`date.ts` | 金额、日期的基础工具 | 无 |
| 领域逻辑 | `src/lib/ledger.ts` | 类型定义、校验、筛选、排序、月份列表、统计、ID 生成 | `money`、`date` |
| 持久化 | `src/lib/storage.ts` | `localStorage` 读写与数据校验 | `ledger` |
| 示例数据 | `src/lib/sample.ts` | 按当前日期生成示例记录 | `date`、`ledger`（类型） |
| 样式 | `src/App.css` | 全局样式与布局，CSS 变量定义主题色 | — |

各模块一览：

```
src/
  main.tsx            入口，挂载 <App />
  App.tsx             状态与组装（75 行）
  App.css             样式（232 行）
  components/
    ExpenseForm.tsx   记账表单：草稿状态、本地校验、错误提示（69 行）
    Filters.tsx       月份/分类筛选控件（38 行）
    Summary.tsx       合计与分类占比条形图（31 行）
    ExpenseList.tsx   明细表格与删除按钮（41 行）
  lib/
    money.ts          金额解析/格式化（22 行）
    date.ts           日期工具（24 行）
    ledger.ts         核心领域逻辑（107 行）
    storage.ts        localStorage 读写（43 行）
    sample.ts         示例数据（19 行）
    *.test.ts         与各模块同目录的单元测试（4 个测试文件）
```

### 3.3 数据流与状态管理

没有引入 Redux、Zustand 等状态管理库，**用 React 内置能力实现单向数据流**：

1. **状态**：`App` 维护两个状态——`expenses`（全部记录）和 `filter`（当前筛选条件）。
2. **派生数据**：用 `useMemo` 从状态计算 `visible`（筛选 + 排序）、`summary`（统计）、`months`（可选月份），避免重复计算，也不额外保存冗余状态。
3. **向下传数据、向上传事件**：父组件通过 props 传入数据和回调（`onAdd`、`onDelete`、`onChange`），子组件不直接改动父状态。
4. **表单局部状态**：`ExpenseForm` 自己维护未提交的草稿和错误提示，调用纯函数 `validateDraft` 校验通过后，才通过 `onAdd` 交给父组件。
5. **持久化**：`useEffect` 监听 `expenses`，每次变化即写回 `localStorage`（`storage.ts` 中以 key `ledger.expenses.v1` 保存）。

数据写入路径：

```
表单输入 → 点「添加」→ validateDraft() ─失败→ 显示错误
                                   └成功→ onAdd(expense) → App.addExpense()
                                        → 生成 id → setExpenses(...)
                                        → 重新计算 visible / summary
                                        → useEffect → saveExpenses(localStorage, ...)
```

### 3.4 数据模型

```ts
interface Expense {
  id: string        // 唯一 ID：时间戳(36 进制) + 随机串，由 newId() 生成
  amount: number    // 金额，单位：分（整数）
  category: Category // '餐饮' | '交通' | '购物' | '住房' | '娱乐' | '其他'
  note: string      // 备注，去空格后 ≤ 30 字，可为空
  date: string      // 本地日期 'YYYY-MM-DD'
}

interface ExpenseFilter {
  month: string            // 'YYYY-MM'，'' 表示全部月份
  category: Category | 'all'
}

interface Summary {
  total: number            // 总额（分）
  count: number            // 笔数
  byCategory: { category; amount; percent }[]  // 按金额降序，percent 取整
}
```

存储格式为上述 `Expense[]` 的 JSON 数组，带版本号的 key（`v1`）为未来数据迁移预留了位置。

### 3.5 设计取舍

| 取舍 | 做法 | 原因 |
| --- | --- | --- |
| 无后端 | 数据只存 `localStorage` | 示例项目定位；零部署成本，打开即用 |
| 金额用整数分 | `parseAmount` / `formatMoney` 边界转换 | 避免 `0.1 + 0.2` 这类浮点误差 |
| 日期用字符串 | 本地 `YYYY-MM-DD`，字符串排序 | 简单、可比较，且不受时区影响 |
| 逻辑与视图分离 | `lib/` 纯函数 + `components/` 展示 | 业务规则可单测；组件替换、样式调整不影响逻辑 |
| 依赖注入 `storage` | 存储函数接收 `storage` 参数 | 测试时传入内存假对象，不需要浏览器环境 |
| 无状态管理库 | `useState` + `useMemo` + props | 状态量小，避免过度设计 |
| 运行时不引第三方库 | 仅 `react`、`react-dom` | `AGENTS.md` 明确要求「不要新增运行时依赖」 |
| 重置示例数据 | 顶部按钮 | 演示时快速恢复初始状态 |

## 四、工程化与质量保障

### 4.1 工具链

| 用途 | 工具 | 说明 |
| --- | --- | --- |
| 开发服务器 | `vite` | 默认 http://localhost:5173 |
| 构建 | `tsc --noEmit && vite build` | 先类型检查再产出静态文件到 `dist/` |
| 类型检查 | TypeScript `strict` | 同时开启 `noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`、`isolatedModules` |
| 单元测试 | Vitest | `environment: 'node'`，只跑 `src/**/*.test.ts`（纯逻辑，无需 DOM） |
| 预览 | `vite preview` | 本地预览构建产物 |

### 4.2 npm 脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动开发服务器 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run test` | `vitest run` |
| `npm run build` | 类型检查 + 构建 |
| `npm run check` | 类型检查 + 测试 + 构建（提交前必跑） |

### 4.3 测试覆盖

测试集中在 `src/lib/`，与实现文件同目录（`*.test.ts`），覆盖内容：

| 测试文件 | 覆盖点 |
| --- | --- |
| `money.test.ts` | 元转分、非法输入拒绝、千分位格式化、负数 |
| `date.test.ts` | 取年月、中文年月显示 |
| `ledger.test.ts` | 表单校验（金额、日期、备注）、按月份/分类筛选、降序排序且不改原数组、月份去重排序、总额与分类占比、空列表 |
| `storage.test.ts` | 保存后可读回、无数据返回空列表、丢弃损坏条目 |

共 4 个测试文件、20 个用例（在当前提交上实测 `npm run check` 通过）。

组件层目前没有测试（未引入 Testing Library / jsdom），这是有意的分层：组件只做展示和转发，核心规则都由纯函数承担测试。

### 4.4 CI

`.github/workflows/ci.yml`：在 `push` 到 `main` 与所有 `pull_request` 时，于 `ubuntu-latest` + Node 22 上依次执行 `npm ci`、类型检查、测试、`vite build`；权限仅 `contents: read`。

### 4.5 协作约定

`AGENTS.md` 规定了「给编程 agent 的约定」：依赖用 `npm ci` 安装；提交前 `npm run check` 全绿；业务逻辑写在 `src/lib/` 并补测试；修 bug 先写复现测试；金额用分、日期用本地字符串；界面文案用简体中文；不加运行时依赖除非 Issue 明确要求；PR 描述写清楚改了什么、为什么、怎么验证。

```sh
npm ci            # 安装依赖

npm run check     # 类型检查 + 测试 + 构建
```

## 六、现状评估

### 6.1 优点

- **结构清晰、职责分明**：UI 与业务逻辑严格分层，模块小（最大 107 行），容易上手和扩展。
- **契约明确**：金额、日期、分类等核心规则集中定义并有测试保护，新增功能时不易破坏已有规则。
- **可测试性好**：纯函数 + 依赖注入（`storage`），测试不需要浏览器，跑得快。
- **工程化完整**：类型严格、单元测试、构建校验、CI 齐全，`npm run check` 一条命令即可验证。
- **轻量**：运行时仅两个依赖，产物小。

### 6.2 已知限制

| 类别 | 限制 | 影响 |
| --- | --- | --- |
| 数据 | 只存本地浏览器，无备份、无跨设备同步 | 清缓存或换设备即丢失；无法多人共享 |
| 数据 | 无导入/导出，无编辑功能 | 只能新增和删除，录错需删掉重录 |
| 功能 | 仅支出，无收入、预算、分类自定义 | 只适合简单记账 |
| 功能 | 不能按日期区间、关键词筛选/搜索 | 记录多时查找不便 |
| 功能 | 删除无二次确认 | 误删不可恢复 |
| 展示 | 明细只显示日期，不显示月份分组 | 跨月查看时略不直观 |
| 工程 | 组件层无测试 | 组件交互回归只能靠人工验证 |
| 工程 | 无 ESLint/Prettier | 代码风格靠约定，无自动检查 |
| 部署 | 无实际部署脚本/页面 | 需自行安排静态托管 |

> 以上为客观梳理，不代表必须修改；部分限制符合「示例项目」的定位。

### 6.3 后续可演进方向（建议）

1. **数据安全**：增加导入/导出 JSON、删除二次确认，降低数据丢失风险。
2. **编辑能力**：复用 `ExpenseForm` 实现记录的编辑。
3. **存储版本迁移**：`STORAGE_KEY` 已带 `v1`，可在模型变更时补迁移函数。
4. **多端/多人（如确有需要）**：引入后端与账号体系，架构上需在 `lib/storage.ts` 处抽象为「仓储接口」，组件层不受影响。
5. **工程补强**：引入 ESLint/Prettier 与组件级测试（Testing Library），纳入 CI。
